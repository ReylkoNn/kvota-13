# Интеграция командного проекта

## Основа и изменения

За основу взят публичный `aufBruderschaft/vacancy-check`, `main`, коммит
`8333a7c4be934de34d6a73449658fab98beeb7f7`; учтена идея кэша и дедупликации из
`554230122bf56b11b63f02969621b30344df1264`. В этой рабочей ветке добавлены его
`main.py`, `app/`, набор `data/kantkod_sample_vacancies.json`. Исходные `src/`
с правилами и ИИ сохранены; `app/integration.py` передаёт им оригинальные вакансии.

В командном `main.py` вызов анализатора подключён вместо TODO; к командному отчёту
добавлены статус и счётчики ИИ. `app/fetch.py` проверяет формат ответа, считает
смещение по числу записей и убирает повторы ID до достижения лимита. Это изменения
относительно версии коллеги, требующие совместной проверки на живом API. Настройки
коллеги добавлены в `config.yaml`, `requests` — в `requirements.txt`. Его правила,
нормализатор и старая функция сохранения находятся в `app/`, но интегрированный
конвейер использует анализатор и нормализатор `src/`, а не оба набора правил одновременно.

Кэширование вызовов модели адаптировано к нашему анализатору: правила выполняются
при каждом запуске, а успешные ответы модели переиспользуются по хешу исходной
вакансии, настроек и кода. Старый `reports/cache.json` с пустой заглушкой не читается;
новый файл — `reports/ai-cache-v1.json`. При ошибке ИИ ответы не сохраняются. `check`
обходит кэш. Изменение весов модели без изменения имени требует ручной очистки кэша.
Расчёт `content_hash` в `app/normalize.py` не используется в этом адаптере, так как
тот нормализатор не включает все исходные поля, нужные анализатору.

Дедупликация из коммита коллеги адаптирована к полям нашей схемы: не объединяем разные
цитаты или разные проблемы только по теме и полю. Предыдущая версия командного
конвейера проверена на реальном API без ИИ и с Gemma на одной учебной вакансии;
последние изменения проверены тестами, в том числе с локальным HTTP и имитацией ИИ.

## Проверка перед передачей

1. `python -m pip install -r requirements.txt`; для модели — ещё `requirements-ai.txt`.
2. `python -m unittest discover -s tests -v` — локальные тесты, с имитацией модели/API.
3. `python main.py check --input data/kantkod_sample_vacancies.json --no-ai --output reports/check.json`.
4. Повторить `check` **без `--no-ai`** на доступной модели и вручную сверить замечания
   с исходными полями. Проверить оба счётчика влияния ИИ, а не только `ai_status`.
5. Проверить `python main.py run` с реальным API, две страницы и уникальные ID;
   по возможности имитировать ошибку API и убедиться, что старый отчёт сохранён.
6. Проверить `python main.py schedule`, интервал и остановку Ctrl+C. Для длительной
   работы организовать постоянный процесс; команды `src.main` и его systemd-примеры
   относятся к альтернативному конвейеру.

Полученный без ИИ пример `data/team_example_report.json` соответствует входу
`data/kantkod_sample_vacancies.json`, предоставленного организаторами. Пример без
ИИ не показывает влияние модели на отчёт.

## Передача в репозиторий коллеги

Сборка подготовлена относительно снимка `5542301`, но новые изменения коллеги могли
появиться после него. Сначала согласуйте передачу и сравните текущие версии `main.py`,
`app/fetch.py`, `app/normalize.py`, `app/report.py`, `config.yaml`. Не заменяйте их
вслепую и не перезаписывайте незакоммиченные изменения коллеги.
Передавать следует исходники, зависимости, тесты, конфигурацию и документацию;
не передавать `.env`, ключи, виртуальное окружение, веса модели, личные данные и кэши.
После объединения повторить проверки выше уже на итоговом коммите общего репозитория.
Публикация с указанием итогового SHA и видео выполняется после согласования командой.
