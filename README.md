# Квота-13 — анализ понятности вакансий (Калининградская область, регион 39)

Прототип для хакатона «Канткод / Онлайн-отбор»: автоматически получает вакансии
с портала «Работа в России» (API региона 39) и формирует JSON-отчёт о том,
насколько понятно описаны условия работы. Отчёт помогает редактору вакансии
подготовить конкретные уточнения для работодателя.

## Интеграция с командной версией (текущая рабочая сборка)

Основа командного запуска — `main.py` и `app/` из репозитория коллеги
`aufBruderschaft/vacancy-check` (основа `8333a7c4`, учтены кэш и дедупликация
из `554230122bf56b11b63f02969621b30344df1264`; адаптация, не копия один к одному).
`app/integration.py` передаёт **исходные** записи анализатору `src/`, который сохраняет
цитируемые поля и объединяет правила и ИИ. Формат командного отчёта — `vacancies[].issues`.
По расписанию запускается именно `main.py schedule`; его настройки в блоках `source`,
`schedule`, `output`, `ai` файла `config.yaml`. Запуск из каталога проекта:

```powershell
# Windows: активируйте подготовленное окружение с Python и установленной Gemma
python -m pip install -r requirements.txt
# Если ИИ-зависимости ещё не установлены, установите также:
python -m pip install -r requirements-ai.txt

# Мгновенная проверка конвейера без модели:
python main.py check --input data/kantkod_sample_vacancies.json --no-ai --output reports/check.json
# Проверка с моделью из config.yaml (может потребоваться авторизация Hugging Face):
python main.py check --input data/kantkod_sample_vacancies.json --output reports/check-ai.json
# API (включает ИИ по умолчанию) и непрерывный запуск через заданный интервал:
python main.py run
python main.py schedule
```

`--no-ai` предназначен для диагностики, не для демонстрации влияния модели. Смотрите
`ai_status`, `ai_generated_issues`, `ai_selected_recommendations`, отдельные `issues`;
`model` равен `null`, если модель не сработала. Проверочный режим анализирует все входные
записи, но ИИ вызывается максимум для `ai.max_vacancies_for_ai` записей; остальные
обрабатываются правилами и fallback. Для больших наборов увеличьте лимит и учтите время.

Настройки `source.max_retries` — **общее число попыток**, включая первую;
`retry_delay_seconds` — пауза между ними. `source.max_pages` ограничивает страницы,
`source.max_vacancies` — число уникальных ID в рабочем режиме. `schedule.every_hours` —
интервал после завершения предыдущего запуска; первый запуск происходит сразу.
Процесс расписания должен оставаться запущенным. Ошибка API пишется также в
`error_report`, а предыдущий успешный отчёт не перезаписывается. Дедупликация по ID
выполняется внутри загрузки. Повторы замечаний дополнительно удаляются консервативно:
разные цитаты или проблемы не объединяются только по теме и полю.

В рабочем режиме (`run` / `schedule`) включён кэш ИИ, настройки — в блоке `cache`.
Он использует SHA-256 всей исходной вакансии, модели, параметров и версии кода анализа;
правила выполняются заново. Отдельные результаты выбора уточнения и анализа сохраняются
только после успешного анализа вакансии. При ошибке модели/fallback новые данные в кэш
не пишутся. Старый `reports/cache.json` коллеги, который мог содержать результаты
заглушки, **не читается**: используется `reports/ai-cache-v1.json`. В режиме `check`
кэш не используется. При диагностике с `debug_dir` кэш также отключён. Установите
`cache.enabled: false`, чтобы выключить кэш в рабочем режиме; результат можно обновить,
удалив только собственный файл кэша. `max_entries` — ограничение числа кэш-записей,
а не вакансий. При обновлении весов модели под тем же именем очищайте кэш вручную.

`ai_cache_hits` показывает число вакансий, для которых был использован хотя бы один
ответ из кэша; `ai_cache_hit` — отметка у отдельной вакансии. Счётчики замечаний и
выбранных рекомендаций включают результаты из кэша и не означают, что модель повторно
вызывалась в этом запуске. Кэш содержит цитаты и потенциально персональные данные,
не публикуйте его. Непрерывные параллельные экземпляры с общим путём кэша не тестировались.

`data/team_example_report.json` получен без модели из файла команды
`data/kantkod_sample_vacancies.json`, предоставленного организаторами. Пример создан
без ИИ и не демонстрирует влияние модели. Предыдущая версия командного конвейера
проверена пользователем с реальным API без ИИ (2 страницы, 6 вакансий) и локальной
Gemma на одной учебной вакансии. Кэш и последние изменения правил проверены тестами
с имитацией модели и API; реальная проверка этих изменений ещё нужна.
Инструкции по передаче изменений и сведения об ограничениях — в `INTEGRATION.md`.

**Важно:** ниже сохранена документация ранее созданной альтернативной точки входа
`python -m src.main`. У неё другие команды, формат отчёта и отдельные плоские настройки
в том же `config.yaml`; она не использует блоки `source`, `schedule`, `output` и
ретраи из командной точки входа. Для интеграции ориентируйтесь на команды выше.

## С чего начинается обработка

**`src/main.py`** — альтернативная точка входа (команды `fetch` / `check` / `schedule` / `resume`).
Конфигурация: **`config.yaml`**. Ключи — только в `.env` (см. `.env.example`), в репозиторий не коммитятся.

## Быстрый старт

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt          # pyyaml и requests

# Проверочный режим (без портала, без модели — правила + fallback):
python -m src.main check --input data/example_input.json --output report.json --no-ai

# Рабочий режим (скачать с API региона 39, минимум 2 страницы):
python -m src.main fetch --no-ai

# По расписанию (ежедневно в 09:00, значение из config.yaml):
python -m src.main schedule
```

## Режимы

| Режим | Команда | Что делает |
|---|---|---|
| Рабочий | `python -m src.main fetch` | Скачивает вакансии с `source_url` (пагинация `limit/offset`, по умолчанию 2 страницы, лимит `max_vacancies`), анализирует, пишет `report.json`. Повторный запуск не плодит дублей: один ID — один объект. При недоступности API код выхода 2, ошибка пишется в `report_error.json`, а **последний успешный `report.json` не перезаписывается**. |
| Проверочный | `python -m src.main check --input <json>` | Тот же анализатор на локальном JSON в формате ответов API (список или объект с `results.vacancies`/`data`/`vacancies`), без обращения к порталу. Именно этот режим использует жюри на своём наборе. |
| Расписание | `python -m src.main schedule [--cron "0 9 * * *"]` | Цикл: каждый день в заданное время сервера — `fetch`; принимается только формат `M H * * *` или `H:MM`. Альтернативы: `crontab.example`, `systemd/kvota13.{service,timer}`. GitHub workflow — демонстрационный stateless запуск без модели; он не сохраняет предыдущий отчёт между запусками. |

Для Калининградской области по умолчанию используется API с кодом региона
`3900000000000`: в одном проверочном запуске он вернул две страницы реальных вакансий.
Доступность API и структура его ответа могут меняться. API опубликован по HTTP;
не передавайте через него ключи или другую конфиденциальную информацию.

Настраиваются в `config.yaml`: `source_url`, `schedule_cron`, `pages`, `page_size`,
`max_vacancies`, `timeout_sec`, `output_report`, блок `ai`. Переопределение без правки
файла: `--source-url`, `--pages`, `--max-vacancies`, `--output`, `--provider`, `--model`, `--no-ai`.

## ИИ: модель, провайдер и шаг использования

**Шаг ИИ в пайплайне:** после проверки правилами модель выполняет две независимые
задачи:

1. Для первого подходящего замечания правила она выбирает **A или B** - один из двух
   подготовленных редакторских вопросов. Выбор модели меняет `recommendation`, но
   `source` остаётся `rule`: проблему обнаружило правило, а не модель. Исходный текст
   сохраняется в `recommendation_original`, выбор отмечен `recommendation_source:
   ai-template-choice`. Это выбор из шаблонов, не генерация моделью текста вопроса.
   Если ответ модели не A/B или модель недоступна, правило остаётся без изменения.
2. Модель дополнительно может самостоятельно найти неоднозначности и вернуть замечания
   с `source: ai`. Их тема, поле и цитата проверяются по источнику; ИИ-заявления о
   противоречиях отбрасываются. При некорректном JSON срабатывает fallback: ответ
   не исправляется автоматически и его частичные объекты не принимаются. В частности,
   модель может забыть экранировать двойные кавычки внутри текста; инструкция просит
   избегать их, но не гарантирует корректный JSON.

В `meta.ai_generated_remarks` и `meta.ai_selected_recommendations` раздельно подсчитываются
два вида влияния модели. `ai_status` показывает `gemma-local`, `transformers-local`,
`api`, `fallback` или `mixed`; `mixed` может означать, в том числе, что выбор вопроса
удался, а свободная генерация перешла на fallback. Статус модели сам по себе не
гарантирует влияние ИИ на результат: проверяйте счётчики и сами замечания. Для вакансии
без замечаний правила выбор шаблона не производится.

Модель получает реальные имена и значения полей источника. Повторы по теме, полю
и цитате объединяются, при этом разные замечания о пропусках различаются по проблеме.
У замечаний ИИ одинаковые поле, цитата, проблема и рекомендация объединяются даже при
разных темах. Ещё две узкие эвристики убирают общий вопрос о требованиях, если конкретные
требования уже есть, общую просьбу указать обязанности и требования, если оба пропуска
уже отмечены правилами, и отдельную неконкретную просьбу перечислить обязанности.
Дополнительные узкие фильтры убирают повтор вопроса об опыте, прямо описанном как
желательный, повтор общего вопроса об обязанностях и один известный дефект грамматики.
Эвристики не гарантируют правильный смысл или грамматику: похожие повторы могут остаться,
а полезное уточнение может быть отфильтровано. Если признаки обязательного опыта есть
в других полях, вопрос об опыте не отбрасывается этой проверкой. Fallback не повторяет
вопрос о сумме оплаты, если он уже задан правилом.
Если часы начала и окончания уже указаны, консервативная проверка отбрасывает отдельные
заявления модели о неизвестной продолжительности рабочего дня; она может пропустить
обоснованное уточнение, например о перерывах. Проверка цитаты не проверяет смысл:
и замечания, и выбранные вопросы нужно проверять редактору; возможны ошибочные и
пропущенные выводы. В журнале видно число предложенных и принятых замечаний до удаления
дубликатов. Выбор шаблона добавляет до одного запроса модели на вакансию; для
API-провайдера это дополнительный сетевой вызов. Данные `example_input.json` синтетические; `kantkod_sample_vacancies.json` предоставлен организаторами.

**Модель и провайдер:**

- `local` (по умолчанию): **Gemma 2 2B IT** (`google/gemma-2-2b-it`) через **Transformers**
  на своём железе. Это gated-модель: может понадобиться бесплатный аккаунт Hugging Face, принятие лицензии и авторизация (`hf auth login`). Веса качаются при первом запуске.
  ```bash
  pip install -r requirements-ai.txt   # transformers + torch
  python -m src.main check --input data/example_input.json   # ИИ включён по умолчанию
  ```
  На CPU это может быть очень медленно. Проверяйте `ai_status`, поскольку при ошибке загрузки автоматически используется fallback.
  Модель меняется через `GEMMA_MODEL` / `--model` / `config.yaml`.
- `api`: OpenAI-совместимый API. Бесплатные варианты без покупки:
  OpenRouter (есть бесплатные модели), Groq (бесплатный tier), Google AI Studio
  (бесплатный tier, Gemini). Скопируйте `.env.example` в `.env`, укажите ключ:
  ```bash
  # .env: AI_PROVIDER=api, OPENAI_API_KEY=..., OPENAI_BASE_URL=..., OPENAI_MODEL=...
  python -m src.main check --input data/example_input.json
  ```
- `off` / `--no-ai`: только правила + fallback-лексикон (мгновенно, без зависимостей).

**Fallback:** если модель недоступна (нет `transformers`, веса не скачались, таймаут,
невалидный JSON) — срабатывает эвристический анализатор (`src/ai.py`, класс
`FallbackAnalyzer`): лексикон неоднозначностей («стабильная зарплата», «дружный
коллектив», «полный соцпакет» и т.д.) + шаблоны уточнений. Отчёт при этом не теряется,
а `ai_status` показывает `fallback`.

**Проверочный режим с моделью без аккаунта и покупки:** после установки `requirements-ai.txt`
используйте открытые веса Qwen (интернет нужен только для первой загрузки; на CPU потребуется время):

```bash
python -m src.main check --input data/example_input.json --provider local --model Qwen/Qwen2.5-0.5B-Instruct --output report.json
```

В отчёте проверьте `ai_status: transformers-local`: если указан `fallback`, модель не загрузилась
или вернула некорректный ответ. Проверяйте `ai_generated_remarks` и
`ai_selected_recommendations`; их нулевые значения означают, что ИИ не повлиял на отчёт.
Gemma и выбор шаблонов уже запускались на реальных вакансиях через альтернативный
конвейер; после последних изменений командную точку входа с реальной моделью ещё нужно проверить.
Влияние открытой Qwen в текущей версии не подтверждено.
В среде разработки доступ к Hugging Face ограничен.
Для целевой роли Gemma используйте модель по умолчанию после получения доступа. Без модели:
`--no-ai` (правила + fallback).

### Кэш и временные файлы на другом диске Windows

По умолчанию Hugging Face и pip могут сохранять данные на системном диске. Перед
запуском модели задайте в PowerShell (букву диска можно изменить):

```powershell
$base = "B:\kvota13-cache"
New-Item -ItemType Directory -Force $base, "$base\tmp" | Out-Null
$env:HF_HOME = "$base\huggingface"
$env:HF_HUB_CACHE = "$base\huggingface\hub"
$env:HUGGINGFACE_HUB_CACHE = "$base\huggingface\hub"
$env:HF_XET_CACHE = "$base\huggingface\xet"
$env:PIP_CACHE_DIR = "$base\pip"
$env:TORCH_HOME = "$base\torch"
$env:TEMP = "$base\tmp"
$env:TMP = "$base\tmp"
.\.venv311\Scripts\python.exe -c "from huggingface_hub import constants; print(constants.HF_HUB_CACHE)"
.\.venv311\Scripts\python.exe -m pip cache dir
```

Запускайте модель в том же окне, иначе переменные нужно установить снова. Эти настройки
не гарантируют отсутствия всех записей Windows и сторонних библиотек на системный диск.
Переназначение `HF_HOME` меняет и место хранения локальной авторизации Hugging Face.

## Диагностический набор для ИИ

`data/ai_probe_input.json` содержит три вымышленные вакансии. Это не оценка модели на
реальных данных и не пример организаторов. Ожидания для ручной проверки:

- `probe-trip` - можно уточнить частоту и длительность регулярных командировок.
- `probe-bonus` - можно уточнить условия назначения премии по решению руководителя.
- `probe-clear` - контрольный пример: конкретные дни и часы указаны в `scheduleText`,
  не нужно утверждать, что они отсутствуют только из-за «гибкого графика» в другом поле.

Запуск на уже загруженной локальной модели, пример путей на Windows:

```powershell
# Сначала настройте HF_HOME/HF_HUB_CACHE/HF_XET_CACHE и TEMP на диск B (инструкция выше).
$env:HF_HUB_OFFLINE = "1"
$env:TRANSFORMERS_OFFLINE = "1"
.\.venv311\Scripts\python.exe -m src.main check --input data/ai_probe_input.json --provider local --model Qwen/Qwen2.5-1.5B-Instruct --temperature 0 --ai-debug-dir B:\kvota13-cache\probe-debug --output B:\kvota13-cache\probe-report.json
```

Модель должна быть полностью загружена заранее: при offline-режиме она не скачается.
`--temperature 0` отключает случайную выборку; результаты всё равно могут различаться
в зависимости от модели, оборудования и версий библиотек. Каждую рекомендацию нужно
проверить человеком. Флаг `--ai-debug-dir` **необязателен**: только при его указании
пишутся отдельные JSON-файлы с входными полями, сырым текстом ответа, ошибкой парсинга
и причинами отклонения кандидатов. Ошибка записи диагностики сама по себе не меняет
статус модели. Если модель не загрузилась до генерации, диагностических файлов ответа
может не быть - смотрите лог и `ai_status`.

Диагностические файлы могут содержать персональные данные и условия вакансий: храните их
вне репозитория, не используйте ключи в текстах и делитесь ими только при необходимости.
Для обсуждения безопаснее использовать вымышленные данные. Результат с `ai_status` модели,
но с нулевыми `ai_generated_remarks` и `ai_selected_recommendations`, **не демонстрирует
влияние ИИ на отчёт**. Ненулевые значения не гарантируют качество - сравните рекомендации
с входными данными вручную.
Проверка в `tests/` использует имитацию модели; новая версия ещё требует запуска на
реальной Qwen или Gemma в среде с доступными весами.

### Сравнение более коротких запросов к модели

Если модель возвращает пустой массив даже на диагностических примерах, можно запустить
отдельный офлайн-эксперимент с двумя короткими запросами: `short_json` (просит замечание)
и `yes_no` (просит только оценку наличия неоднозначности). Это **не рабочий отчёт**:
результаты не добавляются в основной анализатор, а ответы модели нужно проверить вручную.
Эксперимент выполняет шесть запросов для трёх примеров и может быть медленным на CPU.

```powershell
# Заранее задайте HF_HOME, HF_HUB_CACHE, HF_XET_CACHE и TEMP на диск B.
.\.venv311\Scripts\python.exe -m src.ai_prompt_probe --input data/ai_probe_input.json --model Qwen/Qwen2.5-1.5B-Instruct --output B:\kvota13-cache\prompt-probe.json
```

Скрипт включает offline-режим до загрузки Transformers. Если указанной модели нет в
кэше, он завершится с ошибкой и не скачает её. Выходной JSON содержит сырые ответы,
которые могут включать переданный модели текст. Используйте вымышленные данные и не
публикуйте диагностические результаты с персональными сведениями. Тесты этого скрипта
имитируют генерацию; результаты реальной модели остаются предметом ручной проверки.

## Что проверяется

Название, обязанности, требования, оплата, график, место работы, тип занятости —
по описанию **и** структурированным полям API. Если сведения есть в поле, отсутствие
их повтора в описании не считается проблемой. Отмечаются пропуски, неоднозначности
(например, «гибкий график» без дней и смен) и противоречия (оба значения в цитате).
Рекомендации подсказывают, что уточнить, без вымышленных фактов и выводов о нарушении закона.

Правила - ограниченные текстовые эвристики, а не полноценное понимание вакансии:
могут не распознать обязанности, сумму или формат работы либо принять похожее слово
за признак. Нулевые и нечисловые границы зарплаты считаются отсутствующими;
подходящая сумма ищется также в тексте оплаты и рядом с упоминанием оплаты в описании.
Поля `requirement.education`, `requirement.experience` и `requirement.qualification` учитываются как отдельные
сведения; значение опыта `0` само по себе не трактуется как «без опыта». Структурированные
требования не гарантируют, что все нужные требования заполнены. Если в тексте опыт
назван желательным, а в поле опыта есть положительное числовое значение, правило
показывает оба поля и просит уточнение; оно не трактует число как годы или доказанное
противоречие. Сообщение «не удалось
найти» означает результат автоматического поиска, а не установленное отсутствие сведений.
Наши тестовые примеры синтетические; `kantkod_sample_vacancies.json` предоставлен
организаторами. Качество на их наборе и действующем API не измерено; все замечания
требуют проверки человеком.

## Формат отчёта альтернативной точки входа

`report.json`: объект `{"meta": {...}, "vacancies": [...]}`. Для каждой входной вакансии —
отдельный объект с `id`, `url` (ссылка на карточку из источника, иначе `null`), `title`, `ai_status` и массивом `remarks`
(если замечаний нет — пустой массив). `meta` содержит `generated_at`, `mode`
(`fetch`/`check`), `source`, `ai_status`, счётчики.

Каждое замечание: `topic` (тема), `field` (поле источника), `quote` (цитата/значение;
для пропуска — пустая строка; при сопоставлении двух значений они разделяются ` | `;
если они из разных полей, соответствующие имена полей также разделены ` | `;
вложенные поля и элементы списков обозначаются путями вроде `requirements[0]`),
`problem` (суть проблемы), `recommendation` (конкретная рекомендация),
`severity` (`высокая`/`средняя`/`низкая`), `source` (`rule`/`ai`/`fallback`).
Для вопроса, выбранного моделью из двух шаблонов, дополнительно присутствуют
`recommendation_source: ai-template-choice`, `recommendation_original`,
`recommendation_choice` (A/B) и `recommendation_model`. Эти поля отражают настоящий ответ
модели; если выбор не состоялся, они не появляются.

Пример: `data/example_report.json` (сгенерирован из `data/example_input.json`).

### Сценарий видео (до 3 минут)

Запись и публичная ссылка ещё не подготовлены; перед сдачей их нужно добавить в README.
1. Покажите настройку источника, лимита и расписания в `config.yaml`; запустите `fetch`.
2. Покажите `src/ai.py`, затем `check` с доступной моделью и её `ai_status`.
3. Откройте JSON и покажите ID, цитаты и рекомендации, а также fallback при отсутствии модели.
4. По желанию покажите `resume` с вымышленными данными. Проверьте доступность ссылки без авторизации.

Рабочий API из текущей среды проверить не удалось: исходящие соединения к порталу ограничены.
Перед сдачей запустите `fetch` в сети с доступом к порталу и проверьте актуальный формат ответа.

Для постоянного расписания скопируйте unit-файлы из `systemd/` в systemd, исправьте
`WorkingDirectory` и `ExecStart` (укажите Python из виртуального окружения), выполните
`systemctl daemon-reload` и `systemctl enable --now kvota13.timer`. Таймер использует
локальное время сервера; отчёт хранится в рабочем каталоге и не заменяется при ошибке API.
