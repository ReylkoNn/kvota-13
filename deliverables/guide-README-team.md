# Краткая инструкция по заполнению README

Инструкция к [шаблону README](https://github.com/ReylkoNn/kvota-13/blob/ba1e360ba457dc9b07ce52b910b143aaf8141873/deliverables/README-template-team.md). Код, настройки и команды сверены с коммитом команды `ae515451eeeb9e98fa27b31ba62b3761569b4c7d`. Если код изменится, перед публикацией сверьте инструкцию с новой версией.

## 1. Скопировать шаблон

1. Открыть ссылку на шаблон, нажать **Raw**, скопировать весь текст.
2. Открыть `README.md` в репозитории команды и нажать значок карандаша.
3. Вставить шаблон вместо старого текста. Пока не сохранять: сначала заполнить поля и добавить изображения.

Для редактирования нужны права на репозиторий. Если их нет, передать текст участнику с доступом.

## 2. Заполнить поля

- **Участники и вклад:** заменить пять строк таблицы именами или GitHub-профилями и согласованным фактическим вкладом. Не приписывать работу, которую человек не выполнял.
- **Проверенный коммит:** вставить ссылку на тот коммит, на котором команда проверила запуск. Изменение README тоже создаст новый коммит, поэтому SHA окончательной версии сдачи нужно зафиксировать после всех изменений.
- **Видео:** вставить публичную ссылку, убедиться, что она открывается без запроса доступа и ролик не дольше трёх минут.
- **Учебные данные и пример отчёта:** пути уже заполнены. Пример в репозитории — сохранённый пример, не обязательно результат текущего запуска.
- **Остальные разделы:** описание, порядок работы, ИИ, установка, настройки и команды уже заполнены по проверенному коду. Сверить их с итоговым кодом и убрать последние указания в квадратных скобках.
- **Ограничения:** проверить, исправлены ли два отмеченных случая с отклонёнными ответами ИИ и ошибками внутри `results` API. Если исправлены и проверены, обновить текст. Время 3–6 секунд указано как оценка команды и зависит от устройства.

## 3. Подготовить проект для скриншотов

Скачать проект команды, распаковать в отдельную папку и открыть терминал в той папке, где находятся `main.py` и `config.yaml`. Не накладывать новые файлы на старую копию проекта.

Шаблон содержит команды создания виртуального окружения для Windows PowerShell и отдельно для Linux/macOS. Для Windows:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Если активация в PowerShell запрещена, после создания окружения можно выполнить:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Тогда далее вместо `python` использовать `.\.venv\Scripts\python.exe`. Python 3.13 рекомендован командой; в независимой проверке использовался Python 3.11, поэтому работу 3.13 нужно подтвердить на машине команды.

Ollama устанавливается отдельно. Перед `ollama pull gemma4:e2b` проверить свободное место и расположение кэша: скачивание модели может занять несколько гигабайт. На Windows расположение весов задаётся `OLLAMA_MODELS` **для процесса сервера Ollama**, после чего уже работающую Ollama нужно полностью перезапустить. Подробности: https://docs.ollama.com/windows#changing-model-location. Не удалять прежние веса и не загружать вторую копию без необходимости.

## 4. Что сфотографировать

1. **Модель.** При установленной и запущенной Ollama выполнить `ollama list`. Сделать скриншот, если в списке действительно есть `gemma4:e2b`. Этот скриншот подтверждает наличие модели, а не качество её ответов.
2. **Настройки.** Открыть `config.yaml` в редакторе и сфотографировать параметры источника, расписания и модели. Не показывать токены и личные данные.
3. **Запуск.** В терминале выполнить проверку и сфотографировать команду и сообщение о результате:

   ```powershell
   python main.py check --input data/kantkod_sample_vacancies.json --no-ai
   ```

   Это снимок работы **без ИИ**. Если нужен снимок работы с моделью, предварительно запустить Ollama и выполнить эту команду без `--no-ai`, затем проверить фактический отчёт и логи. Запуск перезапишет `reports/report.json`; если старый отчёт нужен, заранее сохранить его копию под другим именем.
4. **Отчёт.** После запуска открыть `reports/report.json` в редакторе и сфотографировать ID вакансии и одно замечание с темой, цитатой, рекомендацией и `source`. Если вместо него показывается `data/example_report.json`, подписать изображение как «пример отчёта из репозитория», а не как новый запуск.

Снимки не должны содержать секреты, токены, переписку или персональные данные.

## 5. Вставить скриншоты в README

Загрузить файлы изображений в репозиторий. Проще положить их в корень и назвать, например, `model.png`, `config.png`, `run.png`, `report.png`. Затем заменить в README строку `[Вставить скриншот ...]` на ссылку на соответствующий файл:

```markdown
![Пример отчёта](report.png)
```

В GitHub можно открыть корень репозитория → **Add file → Upload files** и загрузить изображения, если у вас есть права на запись. Если изображения помещены в папку, путь должен включать её, например `docs/images/report.png`.

## 6. Проверить и сохранить

1. Повторить команды на итоговой версии. Автоматические тесты:

   ```powershell
   python -m unittest discover -s tests -v
   ```

   В проверенном коммите `ae51545` на Python 3.11 прошли 22 теста; они включают имитацию сервиса модели. Это не заменяет реальный прогон Ollama.
2. Убедиться, что все скриншоты, ссылки, имена и описание вклада корректны, а заглушек в квадратных скобках не осталось.
3. Нажать **Commit changes** и сохранить README. Опубликовать видео и зафиксировать финальный SHA после последних изменений.
