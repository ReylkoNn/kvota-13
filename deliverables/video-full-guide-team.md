# Полный гайд по записи видео Vacancy Check

Инструкция для человека, который записывает демонстрацию. Она основана на публичном репозитории команды и коммите `b9dcba72faf3cf3c18565db106628de4b80ef48e`, актуальном на момент подготовки. Перед записью проверьте, не изменился ли код: если изменился, перепроверьте команды и результаты.

**Цель:** за видео до 3 минут показать, что программа получает вакансии, формирует отчёт и как ИИ влияет на результат. Не выдавать готовый пример, кэш или запуск без ИИ за новый успешный вызов модели.

## 1. Что подготовить

Нужны:

- копия проекта команды на компьютере для записи;
- Python и установленные зависимости проекта;
- работающая Ollama с загруженной `gemma4:e2b`;
- учебный файл `data/kantkod_sample_vacancies.json`;
- программа записи экрана с микрофоном, например OBS Studio;
- интернет, если планируете показывать загрузку вакансий по API.

Загрузку модели и установку выполните заранее: ожидание в видео показывать не требуется. Ollama хранит веса отдельно от Hugging Face. Перед скачиванием проверьте свободное место и папку моделей; на Windows её можно настроить через `OLLAMA_MODELS`, затем полностью перезапустить Ollama. Официальная инструкция: https://docs.ollama.com/windows#changing-model-location. Не удаляйте имеющийся кэш и не скачивайте вторую копию без необходимости.

Удобно использовать **новую отдельную копию проекта** для видео: в ней не будет старого кэша отчётов. Не копируйте поверх чужого рабочего каталога и не удаляйте прежние файлы.

### Что открыть на экране заранее

1. Публичный репозиторий: https://github.com/aufBruderschaft/vacancy-check
2. Файл `config.yaml`.
3. Учебный файл `data/kantkod_sample_vacancies.json`.
4. Терминал в папке проекта с активированным виртуальным окружением.
5. Папку `reports` и редактор для просмотра JSON.
6. После подготовки из раздела 3 — два сохранённых отчёта для сравнения.

Уберите из экрана пароли, токены, личную переписку и ненужные уведомления. Используйте учебные данные; не раскрывайте реальные персональные данные. Увеличьте размер шрифта терминала и редактора, чтобы текст был виден в записи.

## 2. Установить и проверить проект

Если зависимости уже установлены, повторно их устанавливать не обязательно. Иначе для Windows PowerShell из папки проекта:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Если запуск скрипта активации запрещён, можно не активировать окружение: вместо `python` в командах ниже используйте `.\.venv\Scripts\python.exe`.

Проверить тесты:

```powershell
python -m unittest discover -s tests -q
```

Для проверенного коммита в отдельной среде Python 3.11 прошли 22 теста. Python 3.13 рекомендован командой, но эту версию необходимо проверить на машине для записи. Тесты имитируют ответы модели; успешный итог `OK` не доказывает качество реальной Ollama.

Проверить, что модель установлена и сервис доступен:

```powershell
ollama --version
ollama list
```

В `ollama list` должна быть `gemma4:e2b`. Если команды не работают — установите и запустите Ollama. Если модели нет, её нужно загрузить заранее:

```powershell
ollama pull gemma4:e2b
```

Локальная модель не требует платного аккаунта. Первоначальная загрузка модели и получение вакансий из API требуют интернета. Модель может частично работать на CPU; скорость зависит от компьютера. Не обещайте фиксированное время обработки без собственного измерения.

В `config.yaml` проверьте `llm.enabled: true`, `llm.base_url: http://localhost:11434/v1` и `llm.model: gemma4:e2b`. При таком адресе запросы к модели идут локальной Ollama. Если указан внешний сервис, текст вакансий отправляется ему.

## 3. Подготовить доказательство влияния ИИ

### Шаг 1. Отчёт без ИИ

Запустить в папке проекта:

```powershell
python main.py check --input data/kantkod_sample_vacancies.json --no-ai
```

Команда создаёт `reports/report.json`. Проверьте в терминале, что обработаны вакансии и отчёт сохранён. Сохраните копию **до следующего запуска**, так как он заменит `report.json`:

```powershell
Copy-Item .\reports\report.json .\reports\report-no-ai.json
```

При необходимости заранее сохраните под отдельным именем предыдущий `reports/report.json`, если он важен: запуск его заменит. Режим `--no-ai` демонстрирует правила, **не работу модели**.

### Шаг 2. Отчёт с ИИ

Убедитесь, что Ollama работает и включён ИИ в `config.yaml`. В новой копии проекта, где ещё нет `reports/cache.json`, выполните:

```powershell
python main.py check --input data/kantkod_sample_vacancies.json
```

Это реальная проверка учебного файла моделью; подождите сообщения о сохранении. По времени она может не поместиться в 3 минуты: подготовьте прогон заранее или в ролике честно сократите ожидание монтажом.

Сохраните отдельную копию:

```powershell
Copy-Item .\reports\report.json .\reports\report-ai.json
```

Если это не новая копия проекта, прежний `reports/cache.json` может вернуть старые ответы. Не удаляйте его наугад: используйте отдельную чистую копию или заранее сохраните кэш в другое место. В логе `использован кэш` означает, что это не новый запрос к модели.

Откройте оба отчёта в редакторе, например в Windows:

```powershell
notepad .\reports\report-no-ai.json
notepad .\reports\report-ai.json
```

В обоих файлах найдите **одинаковый ID**. В отчёте с ИИ выберите конкретное замечание с `source: llm`, которого нет в отчёте без ИИ. Сверьте его цитату и смысл с той же вакансией в учебном файле. Покажите ID, поле, цитату, проблему и рекомендацию.

**Если подходящего `source: llm` нет:** не говорите, что этот запуск продемонстрировал влияние модели. По логу и `llm_status` проверьте, был ли вызов модели, не использовался ли кэш, не отклонены ли её ответы. Команда может отдельно показать `data/example_report.json`, но обязана назвать его **ранее сохранённым примером**, а не результатом показанного запуска. Для подтверждения влияния ИИ нужен реальный корректный результат.

Важно: в текущем коде полностью отклонённый ответ модели может быть отмечен `llm_status: model`, `llm_checked: true` и сохранён в кэш как пустой. Поэтому этих двух полей недостаточно для доказательства полезного вклада ИИ: проверяйте `source: llm` в самом отчёте и логи.

### Удобный пример для показа

В сохранённом командой `data/example_report.json` у `DEMO-39-002` есть ИИ-замечание про формулировку «Выполнение различных поручений руководителя» и правило про отсутствие зарплаты. Используйте этот пример как ориентир, но **не предполагайте**, что новая модель выдаст точно то же. Для ролика лучше показать фактическое замечание из вашего свежего отчёта, если оно обосновано.

В учебном `DEMO-39-003` опубликованный пример содержит замечание правила с двумя значениями опыта в `values`: `0` и «не менее 5 лет». Если показываете противоречие, покажите оба значения и исходные поля, а не только описание.

## 4. Проверка API и расписания — без долгого прогона 200 вакансий

Это необязательная подготовка отдельной демонстрации API. Она не заменяет проверку ИИ: в ней ИИ выключен, чтобы быстро показать получение данных и правила.

Создайте **отдельный** файл `video-api.yaml`, не меняя `config.yaml`:

```powershell
python -c "import yaml; from pathlib import Path; c=yaml.safe_load(Path('config.yaml').read_text(encoding='utf-8')); c['source']['page_size']=3; c['source']['max_vacancies']=6; c['llm']['enabled']=False; c['output']['report_path']='reports/video-api.json'; Path('video-api.yaml').write_text(yaml.safe_dump(c,allow_unicode=True,sort_keys=False),encoding='utf-8')"
```

Запустите:

```powershell
python main.py run --config video-api.yaml
```

Программа попытается получить до 6 вакансий и запишет отдельный отчёт `reports/video-api.json`. Если API недоступен или вакансий меньше, честно покажите фактический результат. Этот запуск — **без ИИ**.

Чтобы отдельно проверить две страницы по 3 записи и вывести только ID, без изменения проекта:

```powershell
python -c "import yaml; from app.fetch import fetch_page; u=yaml.safe_load(open('video-api.yaml',encoding='utf-8'))['source']['url']; a=fetch_page(u,0,3); b=fetch_page(u,1,3); print('page 0:',len(a),'IDs:',[v.get('id') for v in a]); print('page 1:',len(b),'IDs:',[v.get('id') for v in b]); print('unique IDs:',len({str(v.get('id')) for v in a+b if v.get('id')}))"
```

Сравните ID: если страницы повторяются, пусты или запрос завершился ошибкой, не утверждайте, что две разные страницы успешно обработаны. Это отдельная техническая проверка страниц; результаты `run` смотрите в созданном отчёте. Проверяйте, что ID можно показывать публично.

Для расписания в кадре достаточно показать `schedule.every_hours` и команду:

```powershell
python main.py schedule
```

Этот режим **сразу делает реальный API-запрос** и может запустить ИИ на основном лимите вакансий, поэтому без подготовки не запускайте его ради короткого кадра. Можно рассказать о нём по конфигу или отдельно подготовить демонстрационный конфиг с небольшим лимитом и `llm.enabled: false`. Планировщик работает, пока запущен процесс; остановка — `Ctrl+C`. Не выдавайте показ конфига за доказанный суточный запуск.

## 5. Как записать экран

Пример с OBS Studio; можно использовать другую знакомую программу.

1. Откройте OBS Studio и создайте сцену.
2. В «Источники» добавьте **захват экрана** или захват нужного окна.
3. Выберите микрофон и проверьте, что индикатор звука реагирует на голос.
4. Сделайте пробную запись на 5–10 секунд, остановите её и проверьте: виден ли текст, слышен ли голос, не попали ли секреты.
5. Запишите ролик по сценарию ниже. Не переключайтесь на личные сообщения. Если ожидание длинное, можно записать запуск и результат отдельно и сократить ожидание монтажом, сказав об этом.
6. Сохраните ролик в удобном поддерживаемом формате, проверьте звук, читаемость и длительность **до 3 минут**.

Не нужно устанавливать пакеты или скачивать модель прямо в ролике. Это только отнимет время; покажите готовую настройку и реальную проверку.

## 8. Если что-то не получилось

- **`ollama` не найдена:** установить Ollama, открыть новый терминал и проверить `ollama --version`.
- **Модель не найдена:** проверить `ollama list`, место на диске и при необходимости заранее выполнить `ollama pull gemma4:e2b`.
- **Отчёт есть, но ИИ не ответил:** проверьте, запущена ли Ollama, `llm.enabled`, адрес и имя модели в `config.yaml`, сообщения в терминале. Отчёт правил может сохраниться и при ошибке модели.
- **Нет `source: llm`:** модель могла вернуть пустой ответ, её ответы могли быть отклонены или отфильтрованы как дубли. Нельзя делать вывод об успешном влиянии без проверки отчёта и логов.
- **Видео не укладывается:** подготовьте модель и отчёты до записи, сократите паузы монтажом и честно назовите заранее сохранённые результаты.

Независимый тест этой версии проводился на имитации модели и API. Реальные Ollama `gemma4:e2b` и API в среде подготовки этого гайда не запускались; команда должна подтвердить их на своей машине.
