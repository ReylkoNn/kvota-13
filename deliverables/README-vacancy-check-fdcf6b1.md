# Vacancy Check

Программа анализирует вакансии из локального JSON-файла или API «Работа России» и формирует отчёт о пропущенных, неясных и противоречивых условиях. Проверки правил дополняются локальной языковой моделью: для неё используется Ollama и модель `gemma4:e2b`.

Приложение запускается из командной строки; отдельного веб-интерфейса в этом репозитории нет.

## Требования и установка

- Python **3.13**, рекомендованный командой. Запуск автоматических тестов и учебного примера также проверен в отдельном окружении Python 3.11.2; Python 3.13 в этой проверке не запускался.
- Для ИИ — [Ollama](https://ollama.com/download) и загруженная локальная модель `gemma4:e2b`.
- Для первоначальной установки зависимостей и загрузки модели, а также для работы с API, нужен интернет. Локальная проверка уже скачанной моделью не требует платного аккаунта или вызова внешнего платного LLM API. Условия использования модели и доступность установки проверяйте для своего окружения.
- Модель занимает несколько гигабайт; время и потребление оперативной памяти/видеопамяти зависят от компьютера. См. [страницу модели](https://ollama.com/library/gemma4).

Откройте терминал в папке проекта, где лежат `main.py` и `config.yaml`.

### Настройка Ollama

Установите и запустите Ollama. В новом терминале проверьте доступность программы, затем загрузите модель:

```sh
ollama --version
ollama pull gemma4:e2b
ollama list
```

В конфиге по умолчанию ожидается Ollama на `http://localhost:11434/v1`. Ollama должна быть запущена на том же компьютере, что и приложение. Если она уже работает, второй сервер запускать не нужно. Доступ к локальному сервису не требует регистрации в Hugging Face. Если используется внешний OpenAI-совместимый адрес, учитывайте, что на него отправляется текст вакансий.

**Куда сохраняются веса:** Ollama хранит модели отдельно от кэша Hugging Face. Чтобы использовать другой диск в Windows, задайте пользовательскую переменную `OLLAMA_MODELS` **до загрузки модели** и перезапустите Ollama через её значок в трее. Подробно: [Ollama: Windows и расположение моделей](https://docs.ollama.com/windows#changing-model-location). Перемещение переменной не переносит ранее скачанные веса автоматически. Сама программа Ollama, журналы и временные файлы могут при этом находиться в других папках.

## Быстрый запуск

### Локальный учебный JSON

```sh
python main.py check --input data/kantkod_sample_vacancies.json
```

Команда проверяет все записи входного файла с корректными ID; повторяющиеся ID объединяются, при повторе сохраняется последняя запись. Запись без корректного ID вызывает ошибку. Параметр `source.max_vacancies` ограничивает только API, но не локальный файл.

Проверка только правилами, без вызова ИИ и без чтения кэша ИИ:

```sh
python main.py check --input data/kantkod_sample_vacancies.json --no-ai
```

### Ручной запуск через API

```sh
python main.py run
```

Адрес источника, размер страницы, лимит и повторные попытки задаются в `config.yaml`. Программа загружает страницы до достижения лимита или конца данных и объединяет повторяющиеся ID. Фактическая доступность и поведение страниц зависят от внешнего API.

### Запуск по расписанию

```sh
python main.py schedule
```

Первый запуск происходит сразу; следующие — с интервалом `schedule.every_hours`. При ошибке планового запуска следующая попытка ожидается не более часа, если интервал больше часа. Процесс должен оставаться запущенным. Для остановки нажмите `Ctrl+C`; системная служба или планировщик автоматически проектом не создаются.

Для любого из трёх режимов можно добавить `--no-ai`. Вместо стандартного конфига можно указать другой YAML-файл после имени команды, например:

```sh
python main.py check --config config.yaml --input data/kantkod_sample_vacancies.json
```

## Настройки

`config.yaml` содержит:

| Поле | Значение |
|---|---|
| `source.url` | Адрес API источника вакансий |
| `source.page_size` | Размер страницы; приложение может уменьшать его для постраничной загрузки |
| `source.max_vacancies` | Максимум уникальных вакансий при получении из API |
| `source.max_retries`, `source.retry_delay_seconds` | Число попыток загрузки и задержка между ними |
| `schedule.every_hours` | Положительный интервал плановых запусков в часах |
| `llm.enabled` | Включение ИИ; при `false` работают только правила |
| `llm.base_url`, `llm.model` | OpenAI-совместимый адрес Ollama и модель; по умолчанию `http://localhost:11434/v1`, `gemma4:e2b` |
| `llm.max_tokens`, `llm.reasoning_effort` | Параметры генерации модели |
| `llm.api_key_env` | Имя переменной окружения для токена, если выбранный сервис требует его |
| `llm.max_vacancies_for_ai` | Необязательный лимит вакансий для ИИ в одном запуске; остальные всё равно проверяются правилами |
| `output.report_path` | Путь JSON-отчёта, по умолчанию `reports/report.json` |

Не помещайте токены в конфиг или репозиторий. При использовании внешнего сервиса проверьте его требования к защите данных; локальная конфигурация по умолчанию отправляет запросы локальному Ollama.

## Отчёт и пример

Результат по умолчанию сохраняется в `reports/report.json`. Каждый запуск с тем же `report_path` заменяет предыдущий отчёт; запись проходит через временный файл. При ошибке загрузки API до записи старый отчёт сохраняется. Это не означает защиту от любых возможных некорректных ответов API: см. ограничения ниже.

Отчёт содержит время формирования, режим, использованную модель и массив вакансий. Для каждого замечания указываются тема, тип, поле, цитата или значения, описание проблемы, рекомендация и источник:

- `source: rules` — результат правил;
- `source: llm` — результат языковой модели, прошедший проверки приложения.

Темы: **название, обязанности, требования, оплата, график, место работы, тип занятости**. Типы замечаний в отчёте — `missing`, `ambiguous`, `contradiction`. У пропуска цитата может быть пустой; противоречие содержит значения в `values`.

У каждой вакансии есть:

- `llm_checked` — был ли принят ответ модели или кэша;
- `llm_status`: `model` — обработанный ответ модели, `cache` — кэш, `disabled` — ИИ выключен, `error` — ошибка обработки, `skipped_limit` — вакансия пропущена ИИ из-за лимита.

`llm_checked: true` и название модели не гарантируют наличие полезного ИИ-замечания. В текущей версии результат с полностью отклонёнными замечаниями может трактоваться как пустой успешный ответ и сохраняться в кэш. Чтобы подтвердить влияние ИИ на результат, сравните запуск с `--no-ai` и без него и проверьте реальные замечания `source: llm`.

Если Ollama недоступна, в логе появится предупреждение; правила продолжают работать, и отчёт может быть сохранён **без успешной проверки ИИ**. Проверяйте `llm_status`, источники замечаний и логи, а не только сообщение о сохранении файла. Ошибка модели не должна представляться как обнаруженное ею отсутствие проблем.

Проверка цитат и формата снижает риск выдуманных данных, но не гарантирует правильность смысла замечания. Например, наличие адреса само по себе не доказывает обязательное присутствие в офисе: такие выводы нужно сверять с полным текстом вакансии.

## Проверка модели на учебных данных

```sh
python -m tools.verify_model --output reports/model-verification.json
```

Инструмент не использует кэш и делает запросы к настроенной модели. Код выхода `0` означает совпадение с заложенными формальными ожиданиями, `1` — расхождение, `2` — ошибку или недоступность модели. Проверка формы и ожидаемой темы не доказывает правильность смысла, полноту и качество на скрытых данных. В текущей версии полное отклонение замечаний может трактоваться как пустой ответ, поэтому результаты дополнительно проверяйте по логам и вручную.

Автоматические тесты запускаются так:

```sh
python -m unittest discover -s tests -v
```

Интеграционные тесты используют имитацию ответов модели и API; их прохождение не заменяет проверку фактической Ollama и модели.

## Известные ограничения

- Реальная работа модели, скорость и объём требуемой памяти зависят от оборудования и версии Ollama. Если данных для модели нет или сервис недоступен, проверка ИИ не проводится.
- Отклонённые полностью ответы ИИ сейчас могут интерпретироваться как пустой успешный ответ и кэшироваться; результат `llm_checked` нужно трактовать с этим ограничением.
- Пустой объект `results` в ответе API считается концом страниц. Некоторые ошибки, помещённые внутрь `results` без `vacancies`, тоже могут быть приняты за конец данных и привести к частичному отчёту; обработку ошибок источника необходимо усилить.
- Структура вакансий должна соответствовать поддерживаемому формату; запись без ID останавливает обработку, а повторяющиеся ID объединяются.
- Частичная дедупликация и проверки цитат не заменяют экспертную проверку: возможны пропущенные, дублирующиеся или семантически неточные замечания.
- Подключение Ollama локально не требует платного аккаунта, но переносимость установки, доступность модели и воспроизводимость результата должны быть проверены на машине жюри. Скрытый набор не проверялся.
